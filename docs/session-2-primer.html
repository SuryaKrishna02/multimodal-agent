Multimodal Personal Agent

Always on and learning

Now the agent runs as its own process all day, and it improves from your feedback.

The goal: an agent that runs all day and learns

Part 1 waits for you. You press the hotkey or record a note, and the agent answers one time. Part 2 makes the agent run all the time, and it improves from your feedback.

  • Runs all dayagent/daemon.pyIts own process, with a job queue, a schedule and triggers.
  • Survives a crashagent/checkpoint.pyEach step is written down. After a kill, finished steps do not run again.
  • Hears all dayagent/senses/ambient.pyIt cuts the audio at pauses while it arrives. Whisper writes the text.
  • Keeps what mattersagent/memory/consolidate.pyRaw rows become summaries and facts. Each claim cites its rows.
  • Learns from feedbackagent/evolve.pyIt changes its own brief prompt. The locked blocks never change.
  • Two new tasksagent/tasks.pyTask 3 answers questions about earlier events. Task 4 writes a daily brief.

  • At any time: a crashagent/checkpoint.pyKill the daemon in the middle of a job. The next start continues after the last finished step.
  • All day: the dashboarddashboard/It is a second process that reads the same files. The feed shows each job and its reason.

Only three steps need you: the question, the feedback and the reflection.

The map: two processes share one set of files

A kill -9 of the daemon leaves the dashboard up. The next daemon reads the same files and continues.

Memory: screenshots and clips get a vector

  
agent/memory/episodic.py  _scores()

  
def _scores(q: np.ndarray, text_m: np.ndarray, media_m: np.ndarray, mode: str) -> np.ndarray:
    """Score every row for one query. A row without a media vector scores -2 on media (never found by it)."""
    if mode not in MODES:
        raise ValueError(f"mode must be one of {MODES}")
    text_s, media_s = text_m @ q, media_m @ q
    media_s[~media_m.any(axis=1)] = -2.0
    return {"text": text_s, "media": media_s, "both": np.maximum(text_s, media_s)}[mode]

    Four rules that explain Part 2
    
  
      
    
    • 1. The model proposes, code decides_cited(), recall(), validate_patch(), _gate()Code checks each citation, each memory id and each prompt patch before something is stored.
      • 
    
    • 2. Each step is safe to run twiceagent/checkpoint.pyA crash can repeat one step. The window key, the duplicate filter and the stored results make the second run safe.
      • 
    
    • 3. Two processes, one set of filesdata/runtime/*.sqliteThe daemon and the dashboard share only SQLite files. One continues when the other stops.
      • 
    
    • 4. Each part has a number and a limitevals/, config.THRESHOLDSThe cases are synthetic. Add your own recordings and days before you trust a score.
      •
