The goal: an agent that runs on your own machine

  • It listensShort voice clips go to the model as audio.
  • It seesScreenshots and short screen videos go to the model as images.
  • It remembersA SQLite log holds each memory. An embedding search finds it again.
  • It actsLocal Python functions are its tools. Each tool has a permission tier.
Gemma 4Open model, E4B or E2B
llama.cppLocal inference server
0Hosted model APIs or cloud services
Plain PythonYou can read it in one sitting

    Three rules explain the shape of the repo

    • Plug-ins for machinesA file in agent/platforms/ or agent/accel/ holds each OS or GPU difference. Core code never checks sys.platform.
    • One event logEach component calls events.emit(). Library code does not print. The dashboard reads this log.
    • One config fileagent/config.py holds the ports, thresholds and paths, with notes that explain the values.

    From a tool you call to an agent that stays on

    Today, the agent acts only when you speak a note or press the hotkey. It does not run alone, and it does not improve. Part 2 changes both.

    • Kill it in the middle of a taskThe daemon will restart and continue from its last checkpoint.
    • Ask what you decided this morningThe agent will listen, summarize on a schedule, and answer from memory.
    • Correct it, and watch it changeYour feedback on a daily brief will patch its prompt. You will see the diff, and you can go back to any version.
    • Search by picture and by voiceMemory will hold screenshots and audio beside text, in one vector space.
