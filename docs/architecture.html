multimodal-agent architecture

A personal agent that listens, sees, remembers and acts, entirely on the device. Inputs flow through senses and tasks into the brain. The brain talks to a local llama-server running Gemma 4, with memory and a permissioned tool registry on the side. Numbers match the Session 1 segments in the table below the diagram.

Portability layer

Everything that differs by OS or GPU sits behind two plug-in folders. The agent chooses the plug-in at start-up. Core code never branches on the OS. See PLATFORMS.md.

Data flow for one request

  1. A sense produces raw input: a 16 kHz float array, a PIL image or a video file.
  2. brain.part() turns it into an OpenAI-style content part (base64 WAV, PNG or MP4).
  3. brain.fit_budget() adds the system prompt and the top 3 memories. It estimates tokens: audio at 25 per second, an image at pixels / 2304 (up to 1,120), a video at frames x image, text at chars / 4. It drops old history if the request does not fit.
  4. brain.send() writes the exact request to data/runtime/last_request.json, logs it to the event log, and posts it to llama-server.
  5. A reply with tool_calls goes through tools.run(): schema check, tier, guard, execute. The result returns to the model as a tool message and the loop runs again.
